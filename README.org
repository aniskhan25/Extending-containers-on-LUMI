Examples of extending the LUMI AI Factory (LAIF) PyTorch Singularity container
with additional Python packages.

| Container definition        | Purpose                                      |
|-----------------------------+----------------------------------------------|
| =matbench-lumi.def=         | Matbench Discovery 1.3.1                     |
| =matbench-mace-chgnet-lumi.def= | MACE and CHGNet (extends matbench image) |
| =sglang-lumi.def=           | SGLang inference server (MI250x, experimental) |

* Matbench Discovery

This extends a LUMI AI Factory PyTorch container with
=matbench-discovery==1.3.1=.

The image is intentionally minimal. It installs the Matbench Discovery framework
only. Add model-specific packages such as =mace-torch=, =chgnet=, or phonon
extras in a derived image when needed.

* Build

#+BEGIN_SRC bash
export PROJECT=<project>
#+END_SRC

#+BEGIN_SRC bash
export LAIF_BASE=/appl/local/laifs/containers/lumi-multitorch-latest.sif
export SIF=/scratch/$PROJECT/$USER/lumi-matbench-discovery.sif
#+END_SRC

#+BEGIN_SRC bash
srun --account=$PROJECT --partition=small --ntasks=1 --cpus-per-task=8 --mem=120G --time=02:00:00 --nodes=1 --pty bash
#+END_SRC

#+BEGIN_SRC bash
module purge
module load CrayEnv
module load PRoot

mkdir -p /tmp/$USER
export SINGULARITY_TMPDIR=/tmp/$USER
export SINGULARITY_CACHEDIR=/tmp/$USER
#+END_SRC

#+BEGIN_SRC bash
singularity build --build-arg LAIF_BASE=$LAIF_BASE $SIF matbench-lumi.def
#+END_SRC

Use a pinned LAIF base image instead of =latest= for reproducible builds.

* Optional Model Image

Build this only if you need MACE and CHGNet support:

#+BEGIN_SRC bash
export MATBENCH_BASE=/scratch/$PROJECT/$USER/lumi-matbench-discovery.sif
export MODEL_SIF=/scratch/$PROJECT/$USER/lumi-matbench-mace-chgnet.sif
#+END_SRC

#+BEGIN_SRC bash
test -f "$MATBENCH_BASE"
singularity build --build-arg MATBENCH_BASE=$MATBENCH_BASE $MODEL_SIF matbench-mace-chgnet-lumi.def
#+END_SRC

Use =$MODEL_SIF= instead of =$SIF= in the run or smoke-test commands for this
image.

* Run

#+BEGIN_SRC bash
module purge
module use /appl/local/laifs/modules
module load lumi-aif-singularity-bindings
#+END_SRC

#+BEGIN_SRC bash
singularity exec $SIF python -c 'import matbench_discovery as mbd; print(mbd.__version__)'
#+END_SRC

* Smoke Test

The smoke test lives in this repo, not inside the SIF:

#+BEGIN_SRC bash
module purge
module use /appl/local/laifs/modules
module load lumi-aif-singularity-bindings
#+END_SRC

#+BEGIN_SRC bash
singularity exec \
  --bind "$PWD:/repo" \
  $SIF \
  python /repo/scripts/matbench-smoke.py
#+END_SRC

Run it on a GPU allocation if you want to confirm GPU visibility. On CPU nodes,
=torch.cuda.is_available()= should print =False= and continue.

* Notes

- =matbench-lumi.def= creates =/opt/matbench-venv= with
  =--system-site-packages= so it can reuse LAIF's ROCm-enabled PyTorch.
- Matbench Discovery 1.3.1 creates package-local directories at import time; the
  definition pre-creates them while the image is still writable.
- =MPLCONFIGDIR= and =MBD_CACHE_DIR= point to =/tmp= to avoid writes under
  read-only home/package paths.

* SGLang on LUMI (Experimental)

Two files cover SGLang support:

- =sglang-lumi.def= — Singularity image built with =singularity build=
- =scripts/install-sglang-pip-containerize.sh= — alternative using LUMI's
  =lumi-container-wrapper= (=pip-containerize=); closer to how vLLM is
  installed on LUMI today

Both use the same underlying technique described below.

** Status and Caveats

SGLang does *not* officially support MI250x (=gfx90a=/CDNA2).  The official
ROCm targets are MI300X (=gfx942=) and MI350X (=gfx950=).  Two issues apply:

1. *=aiter= not compatible with gfx90a* ([[https://github.com/ROCm/aiter/issues/179][ROCm/aiter#179]]): the default
   =pyproject.toml= pulls in =aiter=, whose =composable_kernel= build includes
   FP8 kernels that gfx90a does not support, causing a build failure.
   SGLang ships =pyproject_other.toml= as the AMD variant, which removes
   =aiter= (and all other CUDA/NVIDIA-only deps) entirely.  Swapping this file
   in before =pip install= is the correct fix.  The =SGLANG_USE_AITER=0=
   runtime env var ensures aiter paths are disabled if they were somehow
   present.

2. *No FlashInfer on MI250x*: FlashInfer's ROCm builds cover MI300X/MI325X/
   MI355X only.  =pyproject_other.toml= does not install FlashInfer.  The
   Triton attention backend (=SGLANG_ATTENTION_BACKEND=triton=) is used
   instead.

Expect reduced throughput compared to MI300X.  Test before production use.

** Known Bad Pattern (Do Not Use)

The following pattern appears in older install attempts and produces a silently
broken install:

#+BEGIN_SRC bash
# WRONG — --no-deps skips petit_kernel, wave-lang, and other runtime deps
python -m pip install --no-deps "$SRC_DIR/sglang/python"
#+END_SRC

The package imports but model inference fails.  Always install with the
=all_hip= extra and without =--no-deps=.

** Option A: Singularity .def (singularity build)

#+BEGIN_SRC bash
export PROJECT=<project>
export LAIF_BASE=/appl/local/laifs/containers/lumi-multitorch-latest.sif
export SIF=/scratch/$PROJECT/$USER/lumi-sglang.sif
#+END_SRC

Request a CPU build node (no GPU needed for the build):

#+BEGIN_SRC bash
srun --account=$PROJECT --partition=small --ntasks=1 --cpus-per-task=8 --mem=120G --time=02:00:00 --nodes=1 --pty bash
#+END_SRC

#+BEGIN_SRC bash
module purge
module load CrayEnv
module load PRoot

mkdir -p /tmp/$USER
export SINGULARITY_TMPDIR=/tmp/$USER
export SINGULARITY_CACHEDIR=/tmp/$USER
#+END_SRC

#+BEGIN_SRC bash
singularity build --build-arg LAIF_BASE=$LAIF_BASE $SIF sglang-lumi.def
#+END_SRC

** Option B: pip-containerize (lumi-container-wrapper)

Run from a GPU allocation on LUMI-G:

#+BEGIN_SRC bash
srun --account=<project> --partition=standard-g --gpus-per-node=1 --time=01:00:00 --pty bash -l
#+END_SRC

#+BEGIN_SRC bash
bash scripts/install-sglang-pip-containerize.sh
#+END_SRC

The script respects =PROJECT=, =SGLANG_VERSION=, and =CONTAINER= env vars.

** Run

For Option A (Singularity image):

#+BEGIN_SRC bash
module purge
module use /appl/local/laifs/modules
module load lumi-aif-singularity-bindings

singularity exec \
  --env HF_TOKEN=$HF_TOKEN \
  $SIF \
  python -m sglang.launch_server \
    --model-path meta-llama/Llama-3.1-8B-Instruct \
    --host 0.0.0.0 \
    --port 30000 \
    --tensor-parallel-size 8 \
    --attention-backend triton \
    --device cuda
#+END_SRC

For a SLURM batch job see =scripts/sglang-serve.sh=.

For Option B (pip-containerize), see the =SUCCESS= output printed by the
install script for the exact launch command.
